O intercâmbio OpenStruct troca **um detalhamento estruturado** por arquivo JSON. Reutiliza a hierarquia da AS-01, o contexto da AS-02 e a comparação/transação da AS-08. Não substitui o projeto aberto, não transporta folhas nem duplica aço por criar outra vista. O [guia de uso](GUIA.md#pacotes-de-detalhamento-openstruct) explica os comandos da interface.

## Contrato aberto v1

- Identificador: `schema: "openstruct.detail/1"`.
- Nome recomendado: `<detalhe>.osdetail.json`, UTF-8, MIME `application/json`.
- [JSON Schema 2020-12](openstruct-detail-v1.schema.json), identificador `urn:openstruct:detail:1`. É uma especificação neste repositório, sem presumir serviço HTTP de integração.
- [Exemplo mínimo em mm](examples/minimal-mm.osdetail.json): quatro barras retas de 1000 mm, Ø10, uma chamada e um rebatimento.
- [Revisão de viga em cm](examples/viga-cm.osdetail.json): a mesma origem, com nova geometria e uma segunda posição de estribos. Importar depois do exemplo mínimo propõe atualizar.
- [Produtor Python](examples/produce-detail.py), sem dependências externas, para adaptar em outros apps OpenStruct.

| Campo                    | Significado                                                                                                                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema`                 | Versão do contrato; uma versão desconhecida é recusada. Não confundir com a versão do projeto ArmaduraStruct.                                                                                  |
| `units`                  | `length`: `mm`, `cm` ou `m`; `angle`: `deg`. Unidades ausentes/desconhecidas são recusadas, sem inferência por tamanho.                                                                        |
| `origin`                 | Identidade canônica `{projectId, floorId, elementId, detailId}`. Define equivalência entre revisões, independentemente dos nomes.                                                              |
| `context`                | `{project, floor, element, detail}`, cada qual com `id` e `name`; o detalhe também informa `grouped`. São IDs do projeto exportador, que podem diferir da origem canônica após uma importação. |
| `producer`               | `{app, version}` identifica o produtor do arquivo; não declara integração automática ou dimensionamento pelo ArmaduraStruct.                                                                   |
| `exportedAt`, `revision` | Data ISO UTC de exportação e texto de revisão. Não são chaves de identidade.                                                                                                                   |
| `metadata`               | Até 100 propriedades textuais, chave até 100 caracteres e valor até 5000; extensões específicas do produtor ficam aqui.                                                                        |
| `objects.bars`           | Posições físicas pertencentes ao detalhe, com ID, marca, tipo, origem, rotação, vértices/dimensões, bitola, mandril, aço, quantidade, distribuição opcional e cor.                             |
| `objects.details`        | Rebatimentos `{id, barId, origin}`. São representações; não acrescentam aço.                                                                                                                   |
| `objects.annotations`    | Cotas, chamadas e cortes, com pontos, texto, altura, cor e `barId` opcional.                                                                                                                   |
| `objects.polylines`      | Desenhos sem dados de aço, com ID, pontos, fechamento e cor.                                                                                                                                   |
| `objects.masks`          | Referências CAD incorporadas em primitivas normalizadas, camadas, transformação, unidade de origem e avisos. Não contêm os bytes DWG originais.                                                |
| `dependencies`           | Definições de posições externas usadas por chamadas/rebatimentos do detalhe. São referências disponíveis para uma decisão, **não aço importado implicitamente**.                               |
| `objectOrigins`          | Um registro `{projectId, objectId}` por objeto físico/gráfico e dependência. A identidade acompanha o ID local remapeado.                                                                      |

Todas as medidas lineares usam `units.length`, inclusive bitola, diâmetro de dobra, ganchos, dimensões de estribo, pontos de distribuição, origens, textos e pontos das referências. Ângulos são graus; contagens são inteiras; escala/opacidade são adimensionais. Os vértices de uma barra livre são locais à sua origem e rotação. Uma representação tem sua origem gráfica separada da origem física. A geometria e a convenção de eixo/dobras são as do ArmaduraStruct, documentadas no README; não é um código universal de forma de fabricação.

Em uma máscara, `scale` continua como transformação adimensional local. O normalizador converte pontos/origem/altura de texto para mm e não reaplica `sourceUnit`: este último campo é informativo. Uma altura de texto ausente usa 2,5 na unidade declarada; a exportação torna o valor explícito. Visibilidade de máscara/camada não muda o aço.

O JSON Schema verifica a estrutura. O importador também verifica regras semânticas: unidades normalizadas e limites do modelo, IDs globais únicos, marcas únicas, origem de cada objeto, uma origem por objeto, grafo de referências fechado e dependências efetivamente utilizadas. Referências sem definição são recusadas em pacotes v1; arquivos de projeto legados continuam com a resolução assistida da AS-08. Dependências não podem colidir com objetos próprios. Os limites atuais incluem 100 MB por arquivo, até 10000 posições físicas contando dependências, 500 vértices por barra e 20 máscaras.

## Produzir em outros aplicativos

Gere IDs persistentes no cadastro do app de origem: mantenha os IDs do projeto/pavimento/elemento/detalhe e das posições entre revisões. Não gere UUIDs novos a cada exportação e não use nomes como identidade. Toda alteração de quantitativo deve atualizar a mesma posição de origem; uma posição nova recebe ID novo.

O exemplo Python é executável, inclusive em Linux e Windows com Python 3:

```bash
python docs/examples/produce-detail.py v1.osdetail.json --quantity 6 --unit cm --revision 02
```

Ele usa os IDs fixos do exemplo para demonstrar reimportação. Antes de usar em produção, substitua `context`, `origin`, IDs de objetos e `objectOrigins` pelos IDs persistentes do seu app. A saída pode ser importada diretamente por **Elementos → Inserir detalhamento**. Para um produtor TypeScript dentro deste repositório, os contratos são:

```ts
const pack = createDetailPackage(project, detailId, {
  unit: 'mm',
  producer: { app: 'Meu app OpenStruct', version: '1.0.0' },
  metadata: { calculationId: 'calculo-estavel-01' },
});
const incoming = decodeDetailPackage(JSON.stringify(pack));
const sourceProject = detailPackageProject(incoming);
// previewDetailTransfer(destination, sourceProject, options) e applyDetailTransfer(...)
```

Os exports estão em `src/domain/detailPackage.ts`. `createDetailPackage` exporta apenas objetos pertencentes ao detalhe, inclui definições de dependências necessárias e preserva origem transitiva. `decodeDetailPackage` valida o contrato/grafo. `detailPackageProject` normaliza unidades e cria uma projeção de transporte sobre o modelo existente para alimentar a AS-08; seu desenho auxiliar de dependências não aparece como detalhe selecionável na interface e não é importado.

Importar usa os mesmos mapeamentos, reassociações, avisos de enquadramento e regras da AS-08. Uma única correspondência de origem propõe **Atualizar**, mesmo tendo sido usado o botão Inserir. Há confirmação para substituir uma origem diferente; homônimos não são equivalentes. IDs/marcas que colidam são remapeados, preservando os vínculos. Dependências já existentes podem ser vinculadas por origem sem alterar seus dados; importar explicitamente uma dependência acrescenta/atualiza essa definição uma única vez.

Dados físicos alterados invalidam a RA bloqueada. Todas as vistas do detalhe consultam a mesma definição, conservando posição/escala/rotação. Cancelar não muda o projeto; aplicar é uma etapa do histórico. Os metadados recebidos persistem em `DrawingDetail.source.exchange` e são reaproveitados na próxima exportação. O projeto permanece `armadurastruct/6`, com esse campo opcional aditivo; as migrações 1–5 continuam intactas.

## Adaptação CAD assistida

Os leitores existentes DXF ASCII/LibreDWG produzem **máscaras**, sem criar aço a partir de linhas ou textos. O comando Interpretar CAD opera nessas mesmas máscaras, com seleção visual ou por lista pesquisável. O usuário escolhe um contorno/eixo, opcionalmente um texto literal para chamada, confirma a escala e atribui explicitamente posição, bitola, quantidade, aço e diâmetro interno de dobra. Não há extração automática de propriedades de textos, inferência de cobrimento ou geração de ganchos.

O contorno passa pela transformação da máscara (escala, rotação e origem) e pela geometria física já existente. Dobras inviáveis e limites de vértices impedem criação parcial. O resultado inclui uma posição física e, quando solicitada, uma chamada vinculada. As primitivas normalizadas da máscara permanecem completas, selecionadas ou não. Uma identidade de atribuição impede contar duas vezes o mesmo contorno; editar ou excluir a posição usa o fluxo comum do editor.

Criação, mudança de escala da referência, chamada e invalidação da RA compõem uma única transação. O contexto isolado só aceita a máscara do próprio detalhe. Com RA bloqueada, é preciso concluir a edição isolada para permitir a invalidação global, conforme o contrato de proteção já existente. As demais posições físicas não são redimensionadas ao mudar a escala de uma referência.

## Verificação e arquivos

Os testes verificam geometrias/quantitativos e vínculos em mm/cm/m, comprimento analítico de 1 m, colisões de IDs/marcas, dependências sem dupla contagem, metadados/origem transitiva, rejeição de contratos inválidos, exportação seletiva sem RA bloqueada e exemplos públicos. Os fluxos no navegador exportam/importam um detalhe nativo, reimportam revisão propondo atualização e conferem cancelar/desfazer/refazer/reabrir. Um DXF sintético comum permanece sem aço até a atribuição explícita; os testes existentes mantêm a leitura DWG real.

Comandos: `npm run check`, `npm run build`, `npm run format:check` e `npm run test:e2e`. A validação funcional é no modo web/Chromium. Os builds de instaladores Linux/Windows continuam na CI; não substituem teste de execução nativa.

## Limites e referência do fluxo

Esta é uma adaptação aberta do fluxo de transferência de detalhamentos, inspirado nas referências de [organização e edição](https://suporte.altoqi.com.br/hc/pt-br/articles/360039699473) e de [inserção/substituição em prancha](https://suporte.altoqi.com.br/hc/pt-br/articles/1500007795461). Não há leitura nativa de `.PRJ`/`.CAD`, importação de dados proprietários de armadura por DWG, nem integração automática demonstrada com Eberick, TQS ou os demais apps OpenStruct. Esses apps podem implementar o contrato publicado para trocar arquivos.

Pacotes transportam a representação física/gráfica suportada atualmente pelo ArmaduraStruct, sem dimensionamento estrutural. CAD curvo é discretizado conforme os leitores e não recupera segmentos analíticos, parâmetros de fabricação ou objetos inteligentes. Entidades não reconhecidas como aço continuam como referência; entidades fora do suporte do leitor (por exemplo, certos proxies/splines/objetos 3D) podem ser omitidas/simplificadas e permanecem explicitamente relatadas nos avisos. O pacote incorpora as primitivas normalizadas, não o arquivo CAD original; conserve este último quando for necessário recuperá-las em outro programa.

A atualização mantém a política de substituição gráfica da AS-08: notas locais ausentes na revisão precisam ser movidas para outro detalhe antes de substituir. A folha pode precisar de reenquadramento após receber geometria maior; escala não é alterada silenciosamente.
